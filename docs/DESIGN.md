# Maester design specification

Status: accepted 10 September 2026 (see [ADR 0002](decisions/0002-web-sveltekit-brutalist-design-system.md)). This document is the visual contract for every page of the Maester web application. It supersedes the proposed colour and typography tokens in [UI specification](UI_SPECIFICATION.md) section 3; that document's layout dimensions, semantic-state rules and accessibility requirements still apply.

The implementation lives in [`apps/web/src/lib/styles/tokens.css`](../apps/web/src/lib/styles/tokens.css) and [`apps/web/src/app.css`](../apps/web/src/app.css). A test, [`design-guard.test.ts`](../apps/web/src/lib/styles/design-guard.test.ts), fails the build when code drifts from the rules below.

## 1. Direction

Refined brutalism, black and off-white. The web is shown for what it is: text, rules, boxes and buttons. Nothing is decorated. Structure is information: a rule marks a real boundary, a number marks a real sequence, a box marks a real record. Type carries the personality; the hero is a sentence, not a statistic. The page demonstrates the product's own rule by showing, for every figure, where it came from, what check ran and whether a person reviewed it.

Reference points, for tone only, never to copy: Bloomberg's sparse text-first homepage, Are.na, terminal interfaces. We take the discipline, not the chaos. Usability research on brutalist sites is clear that chaotic anti-design fails on information-heavy pages, so conventional signposting stays: one primary action per screen, visible navigation, underlined links, real buttons.

## 2. Colour

Exactly three values, defined once in `tokens.css`:

| Token | Value | Use |
| --- | --- | --- |
| `--paper` | `#EDEDE8` | page ground; text on inverted panels |
| `--ink` | `#000000` | text, rules, buttons, inverted panels |
| `--ink-muted` | `#5F5F5B` | secondary text and hairlines on paper only (7.0:1 against paper) |

`--paper-muted` is paper at 72% opacity and is the only secondary text colour allowed on inverted panels. No accent colour, no semantic green or red, no gradients, no tints of black.

Three further values exist for sketched illustrations only, never for text, rules, buttons or state:

| Token | Value | Use |
| --- | --- | --- |
| `--illus-yellow` | `#F2C53D` | illustration colour plate |
| `--illus-red` | `#E0483A` | illustration colour plate |
| `--illus-blue` | `#2F5FD0` | illustration colour plate |

Google's four mark colours exist for the Google sign-in mark only, because Google's branding rules forbid a monochrome G:

| Token | Value | Use |
| --- | --- | --- |
| `--brand-google-blue` | `#4285F4` | Google mark only |
| `--brand-google-red` | `#EA4335` | Google mark only |
| `--brand-google-yellow` | `#FBBC05` | Google mark only |
| `--brand-google-green` | `#34A853` | Google mark only |

The guard fails any file but `GoogleButton.svelte` that names them.

Numerical direction is shown with a sign or a word, never a colour, which also satisfies the product rule that colour must not read as investment advice.

Rules the guard enforces: no hex, `rgb()`, `hsl()`, `oklch()`, `color-mix()` or named colour anywhere except `tokens.css`; components use `var(--…)`, `currentColor`, `transparent` or `inherit`.

## 3. Typography

One family: Archivo, variable, self-hosted from `@fontsource-variable/archivo` (width and weight axes). Fallback stack `"Helvetica Neue", Arial, sans-serif`. No second family, no monospace: numbers and commands use Archivo with `font-variant-numeric: tabular-nums slashed-zero`.

The single exception is `--font-hand` (Caveat, variable, self-hosted from `@fontsource-variable/caveat`), used only for lettering drawn inside a sketched illustration, such as the thought cloud on the sign-in page or what the magnifying glass finds on the not-found page. It never sets interface text.

| Role | Width | Weight | Size | Line height | Tracking |
| --- | --- | --- | --- | --- | --- |
| Display (page `h1`) | 125% | 800 | `clamp(2.75rem, 7.5vw, 6.5rem)` | 0.95 | −0.03em |
| Section heading (`h2`) | 110% | 700 | 28px mobile, 40px from 768px | 1.1 | −0.02em |
| Sub-heading, table title | 100% | 700 | 20–22px | 1.2 | 0 |
| Body | 100% | 400 | 17px | 1.5 | 0 |
| Table cell, note, label | 100% | 400 | 14–16px | 1.45 | 0 |

Sentence case everywhere. No all-caps labels, no letter-spaced eyebrows, no accent word in a headline. Body measure is at most 68 characters. Nothing below 14px.

## 4. Structure and layout

- Rules: 2px `--ink` between sections and around ledgers; 1px `--ink-muted` between rows; 1px `--paper` inside inverted panels. Rules are the only separators. No cards, no shadows, no radius (`--radius: 0`, `--shadow: none`, enforced).
- The register: from 1024px every section is a two-column grid, a 224px rail on the left (the same width the future app shell reserves for its navigation rail) carrying the section label or index, content on the right. Below 1024px the rail folds above the content.
- Width: content is capped at 1440px; gutters are 24px below 1024px and 48px above. Everything is left-aligned. Nothing is centred.
- Breakpoints: 768px and 1024px only. Meaningful content at 360px.
- Wide tables scroll inside a labelled `overflow-x: auto` region. The page never scrolls sideways.
- Numbered markers appear only where the content is an ordered sequence.

## 5. Components

- **Logo** (`Wordmark`): the name on a double rule, the way a total is ruled off in a set of accounts ([brand guide](brand/LOGO.md)). Archivo 125% / 800 as outlines with two rules the full width of the word, drawn inline in `currentColor`, so it is ink on paper and paper on an ink block. It sits in the masthead (30px tall), the terminal rail (26px, 30px from 1024px) and the index footer (24px). Inside a link the link carries the name ("Maester") and the drawing is hidden from screen readers. It never moves: the rules do not draw in, because the page's one motion belongs to the content. The favicon and home-screen icons are the mark, the m on its rules.
- **Button** (`.button`): 2px border, 44px minimum height, 24px horizontal padding, weight 700. Filled ink on paper for the screen's one primary action; `.outline` for secondary actions. Hover and focus invert hard, with no transition. On inverted panels the border becomes paper.
- **Disabled button** (`.button:disabled`): a write action that cannot run here. `--ink-muted` text and a 2px `--ink-muted` border on paper, `--paper-muted` on inverted panels; no fill, no hover inversion, `cursor: not-allowed`. It is a real `<button disabled>`, and it always points at a visible note that says why, through `aria-describedby`.
- **Link**: always underlined, offset 3px, 1.5px thick. Hover inverts to an ink block. Never remove the underline to make a link look like a button; use `.button`.
- **Focus**: 3px solid ink outline, 2px offset, on every interactive element. Paper outline on inverted panels.
- **Ledger** (`EvidenceTrace`, `WorkflowLedger`): a 2px box; header row separated by a 2px rule; body rows by 1px hairlines; figures right-aligned and tabular.
- **Spec list** (`AccuracySpec`): a definition list with a 2px top rule, 1px rules between entries and a 2px closing rule.
- **Tag**: 1.5px border, 4px by 8px padding, 14px text. Used only for the synthetic-data label and status words.
- **Form field**: visible label above the input, 44px input with a 2px border, paper background, error text below the field, status announced through `aria-live="polite"`.
- **Google button** (`GoogleButton`): 48px, full panel width, a 2px border, square, Archivo 700, "Continue with Google" or "Sign up with Google". Google's G at 18px on a 28px paper chip, the only place `--brand-google-*` is used. Filled ink when it is the screen's primary action (on `/login` and `/signup`), outline otherwise. Hover inverts the button; the chip keeps the mark on paper. While it redirects it is disabled and points at the status line.
- **Notice** (`Notice`): a form-level message. A 2px box, a bold first line saying what happened, then what to do; an action (a button or link) may follow. A message that appears in answer to something the person did is announced to screen readers (`role="alert"`, the default); standing text that is there when the page loads, such as "Didn’t get it?" on `/verify-email`, is `role="note"` and is not announced. State is the words, never colour.
- **Or rule** (`OrRule`): between two ways of doing one thing; 1px `--ink-muted` rules either side of a 14px muted label.
- **Password field** (`PasswordField`): a form field with an attached 44px "Show password" button that reveals the text. Its label never changes; `aria-pressed` carries the state, and while pressed the button is an ink block, as the current page is in the terminal rail. An error is a 3px border plus bold text under the field saying the fix.
- **Auth layout** (`AuthLayout`): the sign-in pages' frame — masthead, a 480px panel with a 2px rule, and on `/login` the illustration.
- **Illustration** (`LoginIllustration`): an inline SVG drawn as two plates, a colour plate slightly out of register under a hand-drawn ink plate. It uses `--ink`, `--paper` and the three `--illus-*` tokens and nothing else. Its frame is a 3px rule with a 30px radius on the `figure` that holds it, the one reviewed radius exception (marked `design-guard: allow`); the radius belongs to the drawing, not to the layout, and must not spread to any other element. From 1024px the frame sits to the right of the sign-in panel and fills the screen from the masthead to the bottom edge; below that it stacks under the panel at a square aspect.
- **Due panel** (`DuePanel`): an inverted panel with a 2px paper rule under its header and 1px paper rules between rows. The first item opens with a Trigger, Evidence and Your call spec list; the rest are one-line rows. When nothing is due it lists what was checked.
- **Figure strip** (`FigureStrip`): four headline figures, each with a note saying what it covers. A spec list on a phone, two by two from 768px, one row from 1024px, with 1px `--ink-muted` rules between cells, inside 2px top and bottom rules. An unknown figure is "—" with the reason read out.
- **Holdings table** (`HoldingsTable`): a ledger with all five columns at every width, figures right-aligned and tabular, closed by a 2px totals row. Below the width it needs, it scrolls inside its labelled `.scroll-x` region, which takes focus. An unknown figure is "—" with the reason read out.
- **Sector bars** (`SectorBars`): label, bar and percentage per row, largest first. The bar is drawing only; the label and percentage carry the figure. The unknown bucket is a dashed outline, last, and never a zero.
- **Error sketches** (`LedgerSketch`, `ComputerSketch`, `PlugSketch`): inline SVGs drawn like the sign-in illustration, two plates in `--ink`, `--paper` and the `--illus-*` tokens, each with a text alternative. They are unframed: the sign-in frame's radius does not come with them. `LedgerSketch` (not found) is a ledger with every line empty and a magnifying glass that follows the pointer; under the glass, in `--font-hand`, it finds nothing. `PlugSketch` (offline) is a cable you drag into a socket, which runs the same connection check as the page's "Check again" button and drops back out if the device is still offline. `ComputerSketch` (a page that failed to load) is small and never moves. None of them is a control: each page's way out is a real link or button, first in the tab order.
- **Error page** (`src/routes/+error.svelte`): one page for every error, chosen by `errorView` (`lib/errors/errors.ts`) from the status, the address and the connection: not found, not found inside the terminal, a page that failed to load, offline, signed out (401) and no access (403). Nothing on the static site returns 401 or 403 yet; those two show once the API does. Once a page has shown the offline view it keeps it, and when the connection returns it checks and reloads rather than blaming the server. Public errors use the masthead and the register's rail, with the sentence as the `h1` and the code only as a muted label in the rail. Errors under `/terminal/demo` stay in the terminal shell with section 10's heading sizes; the error page does not read the session, so errors elsewhere in the terminal use the public layout rather than showing a signed-in shell without its account. The play scales down with the stakes: only the public not-found page has a sketch that follows the pointer; inside the shell the failed-page computer is small and still, and the only sketch that moves is the offline plug, on a page with no figures beside it. The build writes the page as `404.html`, which nginx serves for any missing address.
- **Site-down page** (`static/50x.html`): plain HTML that nginx serves when it answers with a 5xx itself. When the container is down, the host's own page shows instead. No script, no motion and no font download; its colours copy `tokens.css` by hand because it cannot load it.
- **Offline banner** (`OfflineBanner`): an inverted line under the terminal's context header while the device is offline, saying when the page last loaded. It is the one other dark block a terminal page may show, and only while offline. It appears and disappears with the connection, with no animation.
- **Section issue** (`SectionIssue`): a section of a terminal page that didn't load, or a step that stopped. A 2px box with a bold first line saying what failed, a line saying what is still current, and an outline "Try again". The rest of the page keeps working, and figures that need the missing data show "—". It announces itself (`role="status"`) unless the page already says what changed through its own status line, where it is a `note`, so each change is said once. While its retry runs, "Try again" is a disabled button pointing at a visible line saying so, and a retry that changes nothing says so in a polite status line ("Still didn’t load."). Documents uses it when the page does not load, and when an opened filing’s answers do not load.
- **Loader** (`Loader`, `Ruler`): a wait with nothing to draw yet. A sentence saying what is being waited for, and the ruler: a 2px rule with an ink block, an eighth of its length and 6px tall, that steps along it, one step every 120ms, eight steps a pass. Nothing shows for the first 300ms, so a quick load never flashes. After 10s it adds "Still working. This is taking longer than usual." and, where the work can be started again, an outline "Try again". The status region is always in the page and the sentence is announced once; the ruler is hidden from screen readers. A wait whose sentence moves on as it goes (the drop strip's "Sending 3 of 12 files…") is not live: it has no status region and no slow line, and the page announces its start and end itself. On an ink panel the ruler draws in paper. It never shows a percentage it cannot keep.
- **Hatch** (`Hatch`): the skeleton piece, a drafting-paper box where a value will be: a 1px outline filled with 45 degree lines in the colour of the text around it. It means "not read yet"; unknown stays "—" or a dashed outline. It is sized to the value it stands in for, so the page keeps its loaded height and nothing moves on arrival, and a box is replaced by its content at once. The lines are an inline SVG pattern, never a CSS gradient. Boxes are hidden from screen readers; the region is `aria-busy` and one status line says what is loading. Documents is the first page to use it, while the filings first load: a filing in the desk's first column and two company groups beside it, in the loaded desk's grid; the Overview follows once holdings are read from the API.
- **Coming soon** (`ComingSoon`): a signed-in terminal page planned for the first release that does not work yet. The page name as the overview's `h1` (section 10) with a "Coming soon" tag, one sentence on what the page will do for the investor and one on what it needs first. No primary action and no button that points at a page that does not work. The page's sketch sits beside the text from 1024px and below it on smaller screens; the text and any link come first in the tab order. Its copy lives in `lib/content/terminal.ts`.
- **Coming-soon sketches** (`RollerSketch`, `CraneSketch`, `BinocularsSketch`, `LampSketch`, `LogbookSketch`, in `components/terminal/sketches/`): one per coming-soon page, drawn like the error sketches, two plates in `--ink`, `--paper` and the `--illus-*` tokens, unframed, with hand lettering in `--font-hand` that changes as you play. Overview: a paint roller that runs dry halfway across a wall. Holdings: a crane whose load will not land on an unfinished wall. Watchlist: binoculars swept along an empty horizon. Analyst: a desk lamp whose cord switches on a light over an empty chair. Activity: a pencil that writes "first entry soon" in an empty logbook. Each moves only under the pointer, never on its own. On a phone a vertical swipe over a drawing still scrolls the page (`touch-action: pan-y`); only the part you drag up, down or round (the crane's load, the lamp's cord) holds the touch (`touch-action: none` on that part). Each snaps with no animation. None is a control or carries information: the lettering sits inside the `role="img"` drawing, whose title is its text alternative, so keyboard and screen-reader users lose nothing. Research, Documents, Market mood and Settings work, so they have no coming-soon page and no sketch.
- **Mood ruler** (`MoodRuler`, in `components/market-mood/`): the market mood on a 0–100 rule. A 2px rule with ticks at every 20, the five band names under it in equal columns (the current band bold, the rest `--ink-muted`), and an 8 by 26px ink block at the score. One `role="img"` labelled "Mood 29 of 100: Cautious"; with no mood it draws no block and says "Mood unknown". Unknown never sits in the middle. On an ink panel it draws in paper.
- **Rank ruler** (`RankRuler`): where a reading sits among its own last 2 years. A 2px rule from "lowest" to "highest", ticks at the ends and the middle, and a 6 by 18px block at the rank. Drawing only: the rank sentence beside it ("Higher than 81% of the last 2 years") carries the figure and labels the image.
- **Score tick** (`ScoreTick`): "In the mood:", a 72px rule with a tick at 50 and a block at the score, then "19 · very cautious". A reading left out of the mood says why in its place ("Not in the mood: no source connected yet."), muted.
- **Reading row** (`ReadingRow`): one market reading in a list inside 2px top and bottom rules, 1px `--ink-muted` rules between rows. From a 40rem container, four columns: the name (an underlined link to the reading's own page), what it measures and the score tick; the value, right-aligned and tabular, with its change; the rank ruler and sentence; the source and the day in words ("Dhan · NSE close · Friday’s close"). Below that it stacks, name and value on one line. A missing value is "—" and the score tick says why.
- **Mood chart** (`MoodChart`): a line over time, ink only, on one axis. For the mood: 0–100 with 1px band lines at 20, 40, 60 and 80, band names at the right when the drawing is 560px or wider, the year's low marked, and the last point labelled "29 today". For a reading: its own domain rounded to whole steps, years on the month labels. Month labels that carry a year keep at least 80px apart, so a phone shows fewer of them; this holds for a reading's two-year chart too. It also draws a share's year of closes on the Research summary, with a wider left gutter for rupee labels and the year's high marked too. Drawn in real pixels from the container's width so its 14px labels never shrink; labels on the line sit on a paper halo. "Show as a table" is an outline button with `aria-expanded` that shows the same figures as a table, newest first, in a labelled, focusable scroll region.
- **Settings group** (`SettingsGroup`, in `components/settings/`): an `h2` and an optional muted lede, then its items, closed by a 2px rule. Settings is a list of groups, so a later setting arrives as a new group or item without a redesign.
- **Settings item** (`SettingsItem`): one accordion item. A 2px rule above, then an `h3` holding a real `<button aria-expanded aria-controls>` at least 64px tall: the item's name (22px, width 110%, weight 700), a one-line muted summary under it, its state in words on the right ("Connected", "Expired 2 Oct"; bold when the item needs you) and + or − as decoration only. The panel's `id` matches `aria-controls`. Several items can be open at once; opening one never closes another. It shows and hides at once, with no motion, and focus stays on the button. On a phone the state takes the summary's place. An item that needs the investor opens on load.
- **Connection section** (`ConnectionSection`): the body of one market data connection in Settings. Not connected, expired, failing or being replaced: the form (client ID and access token for Dhan, API key for FRED, each secret in a password field with "Show token" or "Show key") with "Save and check", and from 1024px a 420px column beside it, "Where to find it", four numbered steps and a link that opens the provider in a new tab. "Save and check" is the screen's one primary action only while Dhan is not connected; otherwise it is outline. While a save checks with the source, the button is disabled and points at "Checking with Dhan…" and the ruler. A refused key gets the fix under its field (3px border, bold text) and the focus; a source that did not answer says so under the form and keeps what was typed. A saved key is never shown again: a spec list gives the client ID, "Ending 9f3c. Saved 6 Oct.", the expiry ("5 Nov 2026, in 30 days") and the last read, with "Replace the token" and an outline "Disconnect Dhan" that asks first in a native dialog ("Disconnect" or "Keep it"). Expired, failing or a Data API subscription that is off each show a Notice (`role="note"`) above the form.
- **Drop strip** (`DropStrip`, in `components/documents/`): where files come in. A 2px dashed `--ink` box (the dashed outline that already means "not there yet" on the sector bars) with "Drop PDFs or XBRL files here", "or", and two outline buttons, "Choose files" and "Choose a folder", that open the system pickers (real `<input type="file" multiple accept="application/pdf,.pdf,.xml,application/xml,text/xml">` and `<input type="file" webkitdirectory>` behind them), and the limit, "PDF or XBRL (.xml), up to 50 MB a file. A whole folder works too.", stated before anything is chosen. Dragging is never the only way; several files or a whole folder can be dragged, and a dropped folder is walked all the way down. Files held over the box invert it hard, as hover does. Each file is checked in the browser: its type (a `.pdf` or an `.xml`, by name and by its first bytes, so a `.pdf` that is not a PDF inside and an `.xml` that is not XML inside are refused; the server checks that an `.xml` is an XBRL instance), the 50 MB limit and an empty file. A folder's system files (`.DS_Store`, `Thumbs.db`, `desktop.ini`) are left out, not refused. The rest go up four at a time, one document per file, through the same upload as a single file. While they go, the box holds one line and the Loader's ruler: "Sending 3 of 12 files from bse-xbrl…" (the file being sent counts), or "Sending ar.pdf…" for one. The line is not live: the page says "Sending 12 files." once at the start and "10 files sent. 2 weren’t added." once at the end, never once per file. Once a batch is done the box takes files again with "12 files sent from bse-xbrl." under the limit. Files that were not added are named in one Notice per batch (`role="note"`, since the end line already announced the count): "2 of the 12 files weren’t added.", then each file's name in bold and why, in the same words whether the browser or the API refused it (`UPLOAD_TOO_LARGE`, `UNSUPPORTED_MEDIA_TYPE`); a list longer than eight scrolls in a labelled, focusable region. Signed out stops the batch: files already started finish, nothing new starts, and the Notice says how many were not sent and links "Sign in". Offline stops it the same way, and the Notice then says “The upload didn’t finish. 214 of 806 files were sent.” and offers “Send the rest”, which sends the files not tried and those that failed offline, in the order chosen; a file that had arrived is marked a duplicate. A file that failed offline after its document was made stays under “Company not known yet” as an unfinished upload, because no document can be removed yet, and a muted line under “Send the rest” says so. One batch at a time: the buttons are disabled while one is checked or sent. Closing or reloading the tab while files are still being sent asks first, because that is the one thing that would stop it; moving to another terminal page does not.
- **Filing list** (`FilingList`, in `components/documents/`): the two lists of filings, Working on and Done, each an `h2` with its count ("4 filings · 7 files", "12 filings"). Filings are grouped by company, each company an `h3` with its codes (BSE, NSE, ISIN) in muted text, and keep the order the API gives: companies by name, filings newest period first. Files with no company are filings of their own, titled by the file name, under “Company not known yet”, last. A filing’s row is the title (an underlined button that opens the filing and moves focus to it), its files in muted 14px text (“XBRL · name”, “PDF · name”, with “Added twice” after a file added again) and, in a 1px `--ink-muted` box, its Numbers and Text tracks in words. Two columns when the list’s container is 36rem or wider, stacked below that. The opened filing’s row carries `aria-current` and a 2px ink rule on its left. Nothing in the list is an ink block; “Needs you” and “Stopped” are bold, and nothing else in a track is. Done shows each company’s newest three filings, with an underlined “Show all 9 filings of Synthetic Cements” that adds " · 1 stopped" when a stopped filing is among the hidden, and then “Show the newest 3”; the opened filing is never left behind it, so a company whose opened filing is past its newest three shows them all, without the button.
- **Filing** (`Filing`): the filing that is open. A 2px box. The company and the filing are its `h2` ("Synthetic Cements · results, quarter to 30 Sep 2026"), under it a muted line giving the bases it holds, the number of files and when it was added. Then, in order: the Numbers track; one ledger per basis, titled "Consolidated", "Standalone" or "Basis not stated", never sharing a row; the Text track; the files; what needs the investor; Read as; and the actions. The Numbers and Text entries are tracks: the one that is working is an ink block, a stopped one carries an outline “Try again”, and the Text entry, once done, says "Done" and "18 pages of the PDF, 2 by OCR, 52 passages; 12 notes from the XBRL". A ledger has the columns Statement, Numbers from and In the PDF. It is built from `div`s with table roles, as the index page’s `Comparison` is, and its rows stack below a 36rem container, with the header row visually hidden and each cell naming its column. Numbers from says "XBRL · quarter and half year" (the spans the instance carries, or "XBRL · at 30 Sep 2026" for a balance sheet), "PDF, read by Gemini · pages 7–8" with the reason muted underneath ("The quarter’s XBRL has no cash flow"), "Not in this filing", or "—" with its reason. In the PDF says "Found: 38 of 38"; a miss is bold ("Found: 51 of 52"), followed by "1 not found." and “Open the results PDF at page n” where the statement pages start, and a check that did not run says why. Each file is listed with its format and when it was added; only a stored file is a link, and it opens in a new tab, while a refused or unfinished file is named in plain text. A file Maester could not tell the kind of holds a Notice that asks “What is it?” with its form. Read as is an `h3` with one `h4` for each file (“PDF · name”), each a spec list of What it is, Company, Period and Statements. Every answer shows where it came from under it: "Page 3: “quote”" (pages counted from 1) for an answer read from a PDF, "Page 3 (scanned): “quote”" when the page had no text layer to check the quote against, "ScripCode 500999" (the element and its value) for an answer read from an XBRL file, "You said so" for the investor’s own, never a confidence. Unknown is "—". What it is and Company carry a "Change" that opens its form in place; a change posts with the answers it was based on, and if they moved on meanwhile it says "These answers changed since you opened them. Here is the latest." and shows them. A company that is not confirmed yet reads "Not confirmed yet". A duplicate has no Read as; it shows as “Added twice” on its first copy. When the answers did not load, a `SectionIssue` says "What Maester worked out didn’t load." with "Try again". The actions are secondary: a "See the figures" link to the company’s page in Research, once the company is confirmed and its numbers are read, and an outline “Read it again”, which reads the XBRL files again, and a PDF only when the filing’s sources still name it, or when nothing in the filing comes from XBRL, and never while an XBRL file of the filing is still being read; never a PDF that XBRL covers, even one Gemini read before its XBRL came. While a track is working, the open filing asks the API for its files every 2 seconds. The filings are read once when one of its files changes filing (identified, held, made a duplicate, kept or read), and every 5 seconds while another filing in Working on is working. Both stop while the tab is hidden, when the page is left and when the investor is signed out. Opening a filing moves focus to its `h2`. A lone upload’s filing takes focus as soon as the file is accepted; a batch holds the open filing on its first file without moving focus. A read never remounts the filing, so it never moves focus by itself. After a Change saves, focus returns to that Change, or, when the file moved to another filing, to the heading of the filing it moved to. A file that becomes held or unnamed while open leaves every filing, and the filing column says "{name} waits for you above." with "Go to it", which moves focus to its row or Notice. Said aloud once: a batch at its start and at its end, and a new question. A track change is never said.
- **Track** (`Track`): one of a filing’s two tracks, Numbers or Text: a label, then two lines of words. Its words are in `lib/content/documents.ts`, and `lib/documents/tracks.ts` (`numbersTrack` and `textTrack`) picks them, for example "From XBRL · reading now", "Page 140 of 286" and "In line, 2 ahead". The first line is bold only for Needs you and Stopped; the second line is muted. In the list a track is words only; in the opened filing the working track is an ink block. It shows counts of pages, passages and figures found, never a percentage or a time left.
- **Companies to confirm** (`ConfirmCompanies`): "Not in your workspace yet", an `h2` with one sentence ("31 companies. Their 214 files wait until you confirm each company, once."). One row for each company a held file prints, however many files wait on it: the name as printed (an `h3`), "9 filings · 26 files", the codes in muted text, then “Add Coastline Bank” and an outline “It’s one of mine”, which opens the picker of the companies already added. A company that matches one already added opens in `pick` mode: "Which of your companies is this?", the matches first and chosen, and “Use this company”, with “Add …” as the outline button. A row that prints no name asks for it and says “Add this company”. Rows are in the API’s order, most files first; past four rows the list shows “27 more companies” and “Show all”. Confirming a row releases every held file that prints that identity, and the page says it once ("Coastline Bank added. Its 214 files carry on."). Files that print no company at all are not a row: each is a Notice, “meridian-q2.pdf: which company is this?”, or, when the file prints a name but no code, “meridian-q2.pdf: is this Coastline Bank?”, with “Say which company”. One filled button on the screen at a time: the first row’s action, else the first unnamed file’s, however many forms are open. No row is drawn until the companies already added have loaded, because a row cannot tell whether it matches one before then.
- **Company list** (`ResearchPage`, in `components/research/`): the workspace's companies in a ledger, name first as an underlined link to the company page, then how many annual reports were read, the latest year and where it stands in words ("Read", "Reading 1 filing", "1 filing didn’t read", "Nothing read yet"; a failure is said before work in progress). In a container narrower than 36rem, Read from and Latest year fold into one muted line under the name, so the list fits a phone. Empty, it says how a company gets there: add a filing in Documents.
- **Stock summary** (`StockSummary`): "The stock and the business". One sentence filled in by rule from the figures, never by a model: the last close and how it compares with a year earlier, then the newest year's revenue and profit. Then a figure strip of four: last close (with the day's change as a sign), 52-week range (with a range ruler), price to earnings (the close ÷ the printed basic earnings per share, with where it was read: the annual report’s page, or an XBRL file’s element; any per-share line when no basic one is printed for the newest year, and then the note says "the earnings per share", not "the basic") and profit for the latest year (with revenue and the change). Revenue, profit and earnings per share come from the statement table's newest year only (the consolidated profit and loss if it has years, otherwise the standalone), and a change compares with the column just before it. A line's name is matched without a list marker ("I.", "(a)") or trailing references ("(Note 25)", "(XI + XIV)"), and the first matching line that the newest year prints is taken, so a line only an older filing prints never hides it; a line with no figure in that year is left out, and nothing older stands in. A year that does not end in March reads "the year to 31 Dec 2025" inside a sentence. A filing in another currency has no price to earnings ("The filing reports in another currency."). A statement in a unit Maester cannot name shows no amounts ("The statement’s unit isn’t one Maester can name."), and a missing profit line says "Profit wasn’t found in the statement." The strip is a list on a phone, two by two when its own container is 36rem wide and four across at 60rem: the container decides, not a fixed breakpoint. The last year's closes follow as a mood chart with the low and high marked and "Show as a table". A price it does not have is "—" with the reason (no NSE symbol, Dhan not connected with a link to Settings, "Maester has no closes for this share yet. It keeps prices for Nifty 500 shares, from your Dhan data.", or the prices did not load); with no price there is no chart. A failed price read is a section issue for the prices only, and the business figures still show. When the statements did not load but the prices did, the prices and the chart still show and the business figures are "—" with "The statements didn’t load."; when an annual report was read but its profit and loss has no dated figure, they say "The profit and loss has no figures Maester could place by year." rather than that nothing was read.
- **Range ruler** (`RangeRuler`): a 2px rule from the year's low to its high, ticks at the ends and a 6 by 18px block at the close. Drawing only: the figure's note says the low, the high and the day of each.
- **Statement table** (`StatementTable`): a ledger with the line names in a sticky first column and one column per financial year, oldest first, each headed by its year and the filing it comes from ("AR 2025–26"). It opens scrolled to the newest years. Sections are row headers; subtotals bold. Each figure is a button: one tab stop, arrow keys move between figures, Home and End go to the ends of a row; the selected figure is an ink block, and a hovered one shows an inset 2px box, not a hard inversion, so hover stays distinct from the selected block. A dash printed on the page shows as "–"; a figure not printed or not readable is "—" with its reason. A restated year is named under its line in words ("2024–25 restated"). A year is restated only when the two filings' figures still differ once both are rounded to the coarser of their printed precisions, so a line printed in lakh one year and in crore the next is not restated by the change of unit alone. A column whose figures come from an XBRL file is headed "Results, XBRL" under its year, in place of the filing. Under the table a note says "Each year comes whole from one filing: an XBRL filing first, otherwise the newest filing that prints it, so a column never mixes filings or sources." and names any figures left out for want of a date and any filing left out for another currency or a unit Maester cannot convert. A statement that was read but has no figure with a date to place it by shows those notes ("6 figures had no date and are left out.") in place of the table, not "not read yet". A per-share line carries "(₹ a share)" and shows the rupees a share as printed, whatever the statement's unit. When a year’s statements come from more than one source (profit and loss from XBRL, cash flow from the annual report), a muted list under the note says so for that year: "2025–26: Profit and loss and balance sheet from the XBRL; cash flow from the annual report, read by Gemini."
- **Figure panel** (`FigurePanel`): the selected figure: its line, statement, basis and period, the figure and its unit, then a spec list: From (filing and "Page 213 of 286"), Restated, On the page, Adds up, Used in, Reviewed ("Not yet"); and "Open the PDF at page 213", which opens the stored PDF in a new tab at that page. "Adds up" is a sentence, never a colour: "Adds up", "Part of total income, which adds up", or, for a sum that fails, "No. The lines add up to {lines}; the page prints {page as printed}, {difference} more|less." The balance identity is said on total assets alone: "No. Total assets doesn’t equal equity and liabilities: the page prints {page}; equity and liabilities come to {sum}, {difference} more|less." The lines under total assets carry only its own subtotal's check, never the identity. "Used in: Price to earnings" appears only on the earnings per share that the summary divides the close by, and only when price to earnings is shown. From 1024px the panel is a column 18 to 22.5rem wide beside the table, sticky and never taller than the window, with its own scroll, so the link to the PDF stays in reach on a short screen. Below that it sits under the table, where choosing a figure moves focus to the panel and "Back to the table" returns it. A figure read from an XBRL file has no page. Its From names the filing and the file, "Results for the year to 31 Mar 2026: the XBRL filed with the PDF" (or "…: the XBRL file" when no PDF of the filing is stored), with the file name and "tagged {element}" under it in muted text; the context is never shown. A Unit entry names the unit and, only where the rounding agrees with the two places shown, the rounding ("₹ crore; rounded to the lakh"), and says "as the filing declares" only when the figure carries the unit the file declares. "In the PDF" takes the place of "On the page" and gives the check in words: "Found on page 5 of the results PDF.", in bold "Not found on the PDF’s statement pages (4–6)." with "The figure stays as filed in XBRL. Check the PDF yourself.", or "Not checked: no PDF of these results is in your documents." and its other reasons. A restatement says what the other filing printed or filed, then whose figure the table shows, which is the one the source that owns the year gives: an XBRL filing owns its year over a newer annual report. A failed sum of an XBRL total says what "the XBRL file gives", never a page. The link is "Open the results PDF at page 5", the page the check found the figure on, else the first statement page, with a muted line saying so and that the XBRL file has no pages; with no PDF of the filing stored there is no link, and In the PDF says why.

## 6. Motion

One non-user-triggered moment per page at most. On the index page the evidence trace resolves its status lines in sequence at 120ms steps, opacity only. Direct manipulation is not an animation: the not-found page's magnifying glass follows the pointer, the offline page's plug moves under it, and so do the parts of the terminal's coming-soon sketches, with no duration and nothing that moves on its own, so there is nothing for reduced motion to switch off. While a page loads, the loader's ruler or the hatch is its one non-user-triggered motion: the ruler steps along its rule, and every hatch box drifts one pixel along its lines each 120ms, all together, so it reads as one current. A page that shows hatch boxes does not also draw the ruler. Both are driven by one clock that sets the step, because the guard caps CSS animation at 300ms and a pass is longer; the clock stops under reduced motion (the block and the hatch hold still) and while the tab is hidden. Everything else snaps: hover, focus and state changes have no transition. Durations never exceed 300ms, `transition: all` is forbidden, and a global `prefers-reduced-motion` rule in `app.css` disables all motion. The guard checks all three.

## 7. Copy

Market the product, not the technology. Public pages describe what Maester does for an investor and the time it gives back; they never mention model names, frameworks, commands, file paths or internal feature IDs. Technical detail belongs in the documentation, not on the page.

Sentence case, plain verbs, written from the investor's point of view. A button says what happens: "See how it works", "Enter the terminal", "Sign in". Maester is a working name. Every mock financial figure carries the label "Synthetic example" or equivalent. Never write "high confidence", a percentage accuracy, or a verified badge that no verification record backs. Say what runs today before what is planned. Unknown is shown as unknown, never as zero. Do not show a link or menu item whose destination does not exist. The one exception: a terminal page planned for the first release may appear in the rail, marked "Soon", and open a coming-soon page that says what it will do (`ComingSoon`).

## 8. Accessibility floor

WCAG 2.2 AA. Semantic landmarks (`header`, `nav`, `main`, `section` with `aria-labelledby`, `footer`), one `h1` per page and sequential headings, a skip link, keyboard-reachable everything with visible focus, 44px targets, text alternatives, status regions rather than colour alone. Tested at 360, 768, 1280 and 1440px and at 200% zoom. `svelte-check --fail-on-warnings` turns the compiler's accessibility warnings into build failures.

## 9. Adding to the system

1. Need a new value? Add a token to `tokens.css` with a comment saying where it is used, and add a row here. Do not add a colour; if a colour seems necessary, the design has gone wrong upstream.
2. Need a new component? Build it from the rules above and add it to section 5.
3. Need an exception? Put `/* design-guard: allow */` on the offending line and justify it in the pull request. Expect the reviewer to say no.
4. Run `pnpm verify` in `apps/web` before opening a pull request. The guard, the type checker and the linter must all pass.

## 10. The terminal

The terminal is the signed-in app. It follows [UI specification](UI_SPECIFICATION.md) sections 2, 12, 13 and 14 and uses the colour, rule and component rules above without change. Four things differ from the public pages: it has an app shell, its gutters are 24px at every width (section 4's 48px from 1024px does not apply), there is no register grid, and its headings are smaller than section 3's, because a working screen leads with data, not a sentence:

| Role | Width | Weight | Size | Line height | Tracking |
| --- | --- | --- | --- | --- | --- |
| Overview `h1` (portfolio name) | 125% | 800 | 32px, 40px from 768px | 1.1 | −0.02em |
| Section heading (`h2`: holdings, allocation, research) | 110% | 700 | 22px | 1.1 | −0.02em |
| Due panel heading (`h2`) | 110% | 700 | 24px, 28px from 768px | 1.1 | −0.02em |
| Due item title (`h3`) | 110% | 700 | 22px, 26px from 768px | 1.2 | 0 |

Body, table, note and label sizes follow section 3, and nothing is below 14px. The overview routes (`/terminal/demo` and `/terminal/demo/quiet`) and every signed-in page use the shell. Signed in, `/terminal/market-mood`, `/terminal/research` (and its company page), `/terminal/documents` and `/terminal/settings` work (see Market mood, Research, Documents and Settings below); `/terminal` (the overview, where sign-in lands), `/terminal/holdings`, `/terminal/watchlist`, `/terminal/analyst` and `/terminal/activity` are coming-soon pages (`ComingSoon`) until each works. Each checks the session itself through `SignedInPage`, not a layout over `/terminal`, because the demo lives under it with no session; signed out, it goes to `/login?next=` that page, query included, so a company page comes back to its company. The implementation is in [`apps/web/src/lib/components/terminal/`](../apps/web/src/lib/components/terminal/) and, for Documents, Research, Market mood and Settings, in [`components/documents/`](../apps/web/src/lib/components/documents/), [`components/research/`](../apps/web/src/lib/components/research/), [`components/market-mood/`](../apps/web/src/lib/components/market-mood/) and [`components/settings/`](../apps/web/src/lib/components/settings/).

**Shell** (`TerminalShell`). From 1024px a 224px rail on the left holds the wordmark, the workspace and the page list, divided from the content by a 2px rule. A 56px context header runs across the content and shows the portfolio as text, and in the demo a "Leave the demo" link to `/`. Below 1024px the rail becomes a 56px top bar, and a Menu button opens the same list, workspace included, as a drawer; Escape closes it and returns focus to the button. The demo's rail lists its one page. Signed in, the rail lists the first release's pages from `lib/terminal/pages.ts` in groups, with a 1px `--ink-muted` rule between them: Overview, Holdings and Market mood; Research, Watchlist, Documents and Analyst; and Activity and Settings at the foot, above the account block. A page that does not work yet (every page but Market mood, Research, Documents and Settings, for now) says "Soon" after its label, in 14px `--ink-muted` (`--paper-muted` on the ink block): a word, never a colour. The underline sits on the label alone. The phone drawer lists the same. The current page is an ink block with `aria-current="page"`. Under a real session the foot of the rail (and of the phone drawer) carries an account block: "Signed in as", the email, and an outline Sign out button that returns to `/`. The demo has no session and no account block. The context header shows the portfolio when there is one, otherwise the workspace name. Search, the portfolio picker and pages beyond the first release are omitted until they exist.

**Overview.** One `h1`, the portfolio name, with two tags, "Holdings snapshot" and "Synthetic example", the as-of date and the read-only note beneath it. The one page-level action, "Update holdings", sits beside the title from 768px and closes the page on a phone. Below it, in order:

1. The due panel.
2. The figure strip.
3. Holdings beside allocation from 1024px, stacked below that.
4. Research updates.

**Due panel.** Inverted, so it is the one dark block on the page; on a phone it runs edge to edge. Decisions come before data fixes: review due, then position limit breached, then missing price, and within each kind the larger portfolio weight first. The subtitle states the count, and the order ("Decisions first, then data to fix.") only when decisions and data fixes are both due. A review stays due once its date has passed, until it is reviewed. The first item expands, when it has a full trigger and evidence detail, into Trigger, Evidence and Your call, and carries "Start the review" (the screen's one primary action) and "Move to next week". The rest are compact rows with a bold title and a muted detail. When nothing is due the panel says so and lists what was checked, because an empty panel with no evidence would read as a missing feature.

**Figures.** In the holdings table, the figure strip, the due rows and the position-limit check, a figure whose input is missing is "—" with the reason available to screen readers, never zero. With no priced holding, known value and the sector bars are unknown, not zero; with no holding that has both a price and a cost, unrealized gain is unknown. Each headline figure carries a note naming what it covers, such as how many holdings are priced. Direction is shown with a sign, never a colour.

**Documents.** `/terminal/documents` is the first page on the real API, under a real session only; it has no demo and shows no synthetic figures. One `h1`, "Documents", and one sentence: "Your filings, by company. A filing’s PDF and XBRL sit together: numbers come from XBRL when there is one, and every page’s text is indexed." Below it, in order: the drop strip (with "Files are still being sent. Moving to another page doesn’t stop them, but closing or reloading this tab does." under it while a batch sends); "Not in your workspace yet", only when some company or file waits for the investor; Working on beside the opened filing from 1024px (the filing first and about 1.3 times as wide); and Done below, full width. Below 1024px everything stacks, with the opened filing first. With no opened filing, or nothing in Working on, the desk is one column. The opened filing is the one the investor opened, else the one that now holds the document they had open, else none while that document waits under "Not in your workspace yet", else the newest filing in Working on, then the newest in Done (`pickFiling`). Maester carries on without waiting: it works out what a file is, and reads annual reports and financial results straight away, with numbers from XBRL when there is any and from the PDF otherwise; a company it has not seen holds its files until the investor confirms it, once; anything else is kept with its company, not read, and its text is indexed. While the page first loads, hatch boxes stand in, in the loaded desk’s grid: a filing in the first column (a heading, two tracks and four ledger rows) and two company groups beside it, with one status line, "Loading your documents."; the drop strip shows, disabled. If the page does not load, a section issue says "Your documents didn’t load." with "Try again"; with no workspace, it says there is none to add documents to. With nothing added it says "Nothing added yet. Drop a filing above, or a whole folder of XBRL files." in place of Working on and Done. A track that stopped says "Stopped" in bold, and the opened filing offers "Try again" for that track only; the other track and the other filings carry on. A filing whose tracks are all settled, a stopped one among them, sits in Done, where "Show all" names how many of the hidden filings stopped. Offline, the banner shows as on every terminal page, and a batch that is sending stops with "The upload didn’t finish. 214 of 806 files were sent." and "Send the rest". Signed out, the polls stop and a Notice, "You’re signed out." with "Sign in to see where your filings stand. Nothing you added is lost." and a "Sign in" link, shows above the drop strip; what was on the page stays under it. The copy lives in `lib/content/documents.ts` and the logic, kept free of Svelte and tested, in `lib/documents/`.

**Research.** `/terminal/research` lists the investor's companies; `/terminal/research/company?id=` is a company's page (the route is prerendered once, so the company travels in the query). It shows real figures under a real session, with no synthetic tag, and has no demo. The list has one `h1`, "Research", and one sentence, then the company list; a company appears once a filing of it is added, and its figures appear once an annual report is read. The company page has one `h1`, the company's name, with its NSE, BSE and CIN, and the annual reports it was read from. Below it, in order: the stock summary; "Statements" with the statement (profit and loss, balance sheet, cash flow) and basis (consolidated, standalone or not stated) toggles; the statement table beside the figure panel from 1024px, stacked below that. Each year comes whole from one filing: an XBRL filing first, otherwise the newest filing that prints it, so a column never mixes filings or sources; lines match across filings by printed name; a renamed line is two rows. Results for a quarter or half year are not in the table yet, and the page names them. Prices are the closes Maester keeps for Nifty 500 shares from the investor's Dhan data. While a page first loads, hatch boxes stand in with one status line. If the statements do not load but the prices do, the summary keeps its prices and chart, its business figures are "—" with the reason, and a section issue under Statements says so with a "Try again" that asks for the statements alone; if neither loads, one section issue says so. An address with no company in the workspace says "This company isn’t in your workspace." "Read from" names each year once, however many copies of its report were read. The copy lives in `lib/content/research.ts` and the logic, tested and free of Svelte, in `lib/research/`.

**Market mood.** `/terminal/market-mood` tells the investor how cautious or eager the market is, from their own Dhan and FRED data. It is personal data, shown only under a real session, never on a public page, with no demo and no "Synthetic example" tag, because the figures are real. It is context for keeping to one's own allocation and never advises. One `h1`, "Market mood", with a tag giving the day in words ("After the close, 6 Oct", or "Provisional, 6 Oct" while an Indian reading is behind the latest session). Below it, in order: the band word at display size and "29 of 100"; one sentence on the band and how many of the 7 scored readings it came from, naming any left out and why; the mood ruler; a fetch Notice (`role="note"`) when the data has never been fetched, the first fetch is running, or the last fetch failed (an expired Dhan token or a refused FRED key links to Settings and says where the readings stop); "The readings", the 10 readings in 4 families (Fear gauges, Money, Breadth and trend, Currency and havens), each a reading row; then the 12-month mood chart beside "How it is worked out" from 1024px, stacked below that. With fewer than 5 scored readings the band is replaced by "Not enough readings to give a mood today."; with nothing stored the sentence says "No readings yet. Maester fetches them after the market closes." Unknown is "—" with its reason, never 0 or the middle of the ruler. Each reading's name opens `/terminal/market-mood/<key>` (prerendered for all 10): "Back to Market mood", the value at 72px with its change, the rank sentence, its 2-year chart with a table view, and What it is, In the mood, Where from and What history says. While a page first loads, hatch boxes stand in with one status line; if it fails, a section issue says so with "Try again". An open page reads the mood again every 10 minutes, but not while the tab is hidden. The copy lives in `lib/content/market-mood.ts` and the logic, tested and free of Svelte, in `lib/market-mood/`.

**Settings.** `/terminal/settings` is a list of accordion groups (settings groups and items), so later settings arrive without a redesign: "Account" with one item, your account (name, email and workspace), then "Connections" with Dhan and FRED, each a connection section. An item that needs the investor (not connected, expired or failing) opens on load; the others start closed. After a save or a disconnect, focus returns to that item's header and one polite status line says what changed ("Dhan connected."). The keys are checked with the source before they are kept, stored encrypted and never sent back: only their last 4 characters show. The copy lives in `lib/content/settings.ts` and the logic in `lib/settings/`.

**Demo.** `/terminal/demo` shows the overview with items due and `/terminal/demo/quiet` shows it with nothing due. Both are prerendered, marked `noindex`, built from a synthetic portfolio and tagged "Synthetic example". Write actions cannot work in a read-only demo, so "Start the review", "Move to next week" and "Update holdings" are disabled buttons that point at the visible note "Read-only demo. Decisions and updates arrive with your account." The demo is linked from one place, the index page's "Where we are" section; no terminal page links to it, and nothing under a real session shows synthetic numbers.
